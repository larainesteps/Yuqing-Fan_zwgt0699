# Appendix A
# External Materials

This appendix records what in the submitted work was obtained from a third party rather than
written for this project. Versions are those installed in the submitted repository, read from
the lock files and the virtual environment on 26 August 2026.

Two datasets were used, on different licence terms, and both are redistributed with the source
code. The scheduling experiments run on the *Medical Appointment Scheduling System* dataset
published by Gonzalez Galtier (2024) under a Creative Commons Attribution 4.0 licence; it is
available at
https://www.kaggle.com/datasets/carogonzalezgaltier/medical-appointment-scheduling-system. The
published file supplies appointment timing, duration, waiting time and demographics only, and
the eleven surgical scheduling columns this project requires were derived from it, so the copy
included at `data/appointments/` is a derivative work redistributed under the same licence. The
attribution and the list of derived columns are recorded in `data/appointments/README.md`.

The clinical case narratives come from the PMC-Patients corpus of Zhao et al. (2023), assembled
from PubMed Central open-access articles and described at
https://doi.org/10.1038/s41597-023-02814-8. That corpus carries a Creative Commons
Attribution–NonCommercial–ShareAlike licence, which restricts commercial use and requires
derivatives to carry the same terms; a permissive repository-wide licence must therefore not be
applied to `data/pmc-patients/`. No narrative text in that directory was written by the author.

The optimiser is built on Google OR-Tools (Perron and Furnon, n.d.), version 9.15.6755, released
under the Apache 2.0 licence and documented at https://developers.google.com/optimization.
OR-Tools supplies the CP-SAT solver only: the constraint model, the candidate enumeration of
Section 4.2 and the dependency-free fallback search engine were written for this project. The
services run on Python 3.13.5 and Node.js 24.19.0, with data held in MySQL Community Server
8.0.28.

The interface uses React 19.2.7 with Vite 6.4.3, and the API uses Express 5.2.1 with the mysql2
driver and Zod for request validation, all under MIT licences, with TypeScript 5.9.3 under
Apache 2.0. On the Python side only `ortools` and `pydantic` 2.13.4 are direct dependencies; the
four services deliberately use no web framework, running instead on
`services/common/runtime.py`, a wrapper over the Python standard library written for this
project (Section 4.1). Exact versions and licences for every transitive dependency are recorded
in `package-lock.json` and `requirements.txt`.

One optional external service is used. The OpenAI API provides one of the two clinical-text
extraction paths; the system runs without it, falling back to the deterministic rule engine, and
records which path produced each extraction. Only the 100 synthetic benchmark notes were ever
transmitted. No appointment record and no PMC-Patients narrative was sent to any external
service, and Section 1.4.1 sets out the privacy reasoning behind that restriction.

Finally, the report itself was converted from Markdown to Word with pandoc 2.12, and the
interface screenshots of Figures 4.2 to 4.7 were captured by driving Microsoft Edge 151 through
puppeteer-core. Every figure in this report was generated by scripts written for this project,
held in `docs/report/figures/`, which read directly from the experiment database; none was drawn
by hand or produced by a third-party charting library.

# Appendix B
# Ethical Issues Addressed

This appendix records what was done in support of the position set out in Section 1.4.

No ethical review application was required. The project recruits no human participants,
processes no personal data and uses no identifiable patient records. Development and evaluation
used synthetic case text written for this project, the publicly available PMC-Patients corpus
(Zhao et al., 2023), and the synthetic appointment dataset of Gonzalez Galtier (2024), whose
publisher states that it was generated synthetically. No data was obtained from a healthcare
organisation.

⟨If your School required an ethics form or a supervisor sign-off even for a project with no
human participants, state that here and attach the form.⟩

Real clinical data would have fallen under what the Information Commissioner's Office classifies
as special category data, whose processing requires both a lawful basis and a separate Article 9
condition; the guidance is at
https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/lawful-basis/special-category-data/what-is-special-category-data/.
The project avoids that position rather than attempting to satisfy it, so no identifiable record
enters the system at any point. The one route by which clinical text can leave the machine is
the optional language-model extraction path, and the interface shows a de-identification warning
before a note can be submitted through it.

Human oversight is enforced in software rather than recommended in prose. Requirement N1 states
that no extraction may reach a schedule without human approval, and no API route can create an
approved case: every extracted record enters a `REVIEW_REQUIRED` state, and the reviewer sees
the original note beside the structured record together with any validation warnings. The
safeguard is not optional because schema validation establishes form and not fidelity — a
fabricated clinical detail yields a well-formed record that passes every automated check (Omar
et al., 2025). Section 5.1 records that two of the three tests asserting this invariant are
skipped in a default run, which is a gap in the evidence rather than in the design.

Fairness is reported, not claimed. The Jain index compares workload allocations without
certifying any of them as equitable, since equal case counts ignore experience, continuity of
care and contracted hours. The priority score is a planning aid and not a clinical triage
instrument: it orders and weights but never accepts or rejects a case, and its components are
exposed for inspection. Review decisions, optimisation requests and results, rejections, locks
and emergency changes are all persisted with a before-and-after record for every transition, so
any schedule the system produced can be reconstructed and questioned after the fact.

The limits should be stated plainly. This is research software: it is not a medical device, it
has not been clinically validated, and no claim of clinical effectiveness or deployment
readiness is made anywhere in this report. Extraction accuracy on real clinical prose is
unmeasured. Operational use would require legal and regulatory assessment, clinical risk
management, security testing, organisational approval and evaluation against representative
data, none of which lies within the scope of an MSc project.
